# Changelog

Behavior changes to pyrtma are recorded here, under "Unreleased", in the same change
that makes them. The version number is chosen at release time.

## Unreleased

### Removed

- The timecode message header (`TimeCodeMessageHeader`) and the `timecode` argument of `Client`, `client_context` and `MessageManager`, with the manager's and the examples' `-t/--timecode` option. Only Python clients could produce that header; the C, MATLAB and JavaScript compilers never did. `get_header_cls()` takes no argument and always returns `MessageHeader`. The standard header is unchanged.
- Positional arguments after `host_id` in `Client` and `client_context`, and after `port` in `MessageManager`. They are keyword-only now, so a call that passed `timecode` positionally raises `TypeError` instead of shifting the arguments after it.
- v1 message definitions, the Python definitions the old v1 compiler wrote from C headers, with that compiler, `pyrtma.compilers.python_v1`. `python -m pyrtma.compile` and `pyrtma.compile.compile()` raise `FileFormatError` for a `.h` file, saying to compile from YAML. Definitions whose message classes have no `type_hash` or `type_size`, as v1 output has, raise `MessageDefinitionsLoadError` naming those classes when they are loaded; before, they loaded with a `DeprecationWarning`, and sending one warned with a `FutureWarning`. Recompile any v1 definitions from YAML. Message classes also no longer convert between `str` and `bytes` for `char` fields declared directly in `_fields_`, which only v1 classes had: such fields now behave as plain ctypes fields, reading as `bytes` and taking only `bytes`. Fields declared with validators, as compiled definitions have them, still read and take `str`. Without that conversion, reading or writing any field of a message or header skips a Python-level hook, which made each access several times slower: in a sandbox, a header field read went from about 330 ns to 70 ns, and `send_message` of a 128-byte message from about 17 µs to 11 µs.

### Added

- `Client.connect(timeout=...)`, keyword-only: one deadline, in seconds, for the TCP connection and the manager's ACK together. The default is 5 seconds; `None` waits as long as it takes. A connection to an unreachable host used to wait for the operating system's limit, from about 20 seconds to minutes. The host name lookup isn't bounded by it.
- `Client.connect` accepts a server name without a port, such as `"localhost"`, and uses port 7111 (`pyrtma.client.DEFAULT_PORT`).
- `MessageManager(stall_timeout=...)` and the manager's `--stall-timeout SECONDS` and `--no-stall-timeout` options. A client that sends part of a message and then nothing more for this long is dropped, with a warning giving the bytes received. The default is 5 seconds; `None`, or `--no-stall-timeout`, never drops it, for example while it is paused at a debugger breakpoint. A stalled client doesn't hold up other clients either way.
- `MessageManager(logger_timeout=...)` and `--logger-timeout SECONDS`. A logger module that can't take a message for this long is dropped, with an error, a `FAILED_MESSAGE` and a `GOODBYE`. The default, `None`, keeps the current behavior of waiting for loggers as long as it takes.
- The message manager allows at most `MAX_MODULES` (256) connected modules. A `CONNECT` beyond that is refused, with an error, and its connection closed.
- The manager refuses a connection that `select()` couldn't watch, with a warning, instead of stopping: past 512 sockets on Windows, or with a descriptor numbered 1024 or higher on Linux and macOS. A manager whose listening socket would be beyond that limit raises `RuntimeError` when constructed.
- `RTMALogger.close()` removes and closes the logger's handlers. It runs by itself when the logger's client is garbage collected.
- `RTMA_UnifiedLog(retry_delay=..., max_retry_delay=..., sleep=...)`, keyword-only, and `RTMA_UnifiedLog.stop()`, which makes `start()` return from another thread. `pyrtma.unified_console_log` also has `parse_args()` and `main()`; `python -m pyrtma.unified_console_log` runs `main()`.
- `pyrtma.web_manager` has `parse_args()`, `run()` and `configure_logging()`, and `main()` takes an optional argument list.
- `DatasetWriter(clock=...)`, keyword-only: the clock for its write and subdivide schedule and its elapsed time, injectable for tests. `DatasetWriter.failed` is True once writing has failed and the dataset has stopped recording.
- `DataLogger.stop()`, which makes `run()` return from another thread, and `DataLogger(clock=...)`, keyword-only, the clock its datasets schedule writes with.
- `UnknownMessageType` and `InvalidMessageDefinition` raised by `Client.read_message` carry the received message's header as `header`, so a caller can tell which type failed. It is a new attribute of `RTMAMessageError`, `None` when an exception wasn't raised for a received message; the exceptions' arguments are unchanged.
- `DatasetWriter.started`, and `pyrtma.data_logger.dataset_writer.error_message()`, which builds a `DATA_LOGGER_ERROR` that always fits its fields.
- `DataFormatter.max_bytes`, 500,000,000 bytes by default: no file the data logger writes grows past it, whatever its formatter. When a file is full, the dataset continues in the next file, numbered `rec_0001`, `rec_0002` and so on; each file is complete and gets its own `DATASET_SAVED`. A file always holds at least one message. A lab can change the limit by subclassing a formatter.
- `DataFormatter.write()` returns how many messages it wrote, and `DataFormatter.discard()`, which does nothing by default, releases what a formatter holds when writing fails. Formatters that override `write()` and return None are treated as having written everything and aren't split. A formatter that takes no messages even into a new file fails its dataset with `DatasetWriterError`.
- `pyrtma.data_logger.cli.parse_msg_types()`, which parses message types as the CLI takes them: `all` or `*`, or IDs separated by spaces or commas. `cli.add_dataset()` takes the client to send with.
- `signed char` fields work, as a one-byte signed integer: `c_int8` in Python, `signed char` in C, and `int8` in MATLAB. The parser listed the type but failed on it with `KeyError`.
- `pyrtma.parser.MAX_REFERENCE_DEPTH` (16): how deeply constants may be defined in terms of other constants, and how long a chain of aliases may be. A constant of numbers only has depth 0, and one that uses other constants is one deeper than the deepest of them. Deeper definitions raise `RecurisionError`, which is now also a `RecursionError`, as before.
- `ConstantString.text` holds a string constant's text. `ConstantString.value` is still the double-quoted literal, now escaped.
- `pyrtma.parser.GeneratedSourceError`, a `ParserError`: the Python compiler raises it, and writes nothing, when the code it generated isn't valid Python.
- `pyrtma.parser.Field.padding`, True for the padding fields the parser inserts. `Parser.definition_hash()` builds a struct's or message's hashed text and hash, `Parser.field_text()` a field's line in it, and `pyrtma.parser.CANONICAL_TYPE_NAMES` holds the name each native type has there.
- `--combined` also writes `<name>_combined.defs`, an index for the combined YAML file with `import_coredefs: false`, since that file holds the core definitions already. `python -m pyrtma.compile -i <name>_combined.defs` compiles it.

### Changed

- Type hashes cover each struct and message as written and as resolved (H9). A hash is still the first 32 bits of a SHA-256 over the definition's text, its name, its ID for a message, and a line per field, but each line now has the field as written, ignoring spacing, and what it resolves to: an alias is followed by its final type (`age: AGE -> int32`), a length written with constants or an expression by its value (`name: char[MAX_NAME_LEN=32]`), and a struct or message by its own hash, which covers its name and fields (`pts: PT[2] -> POINT hash=1a2b3c4d`). A native type has one name per type: `int` and `int32` are both `int32`, `byte` is `uint8`, and `signed char` is `int8`. The padding the parser inserts is included, as `uint8` fields, and `fields: OTHER` contributes the copied fields. A change to a constant's value or name, to an alias's name or target, to a nested struct, including its name and its fields' names, or to the padding now changes the hash of every message that uses it; spacing in a field spec, or another name for the same native type, doesn't. Signals, and definitions written only with canonical native types and literal lengths that need no padding, keep their hashes; every other hash changes, including those of 34 of the 53 core messages, such as `CONNECT_V2` and `SUBSCRIBE`. Message layouts and the header are unchanged. **Rebuild every module's definitions, in every language,** with `build_all_msg_defs.sh` or `.bat` and the lab's own compile steps: a module built before compares hashes in `read_message(sync_check=True)` and `Message.from_json`, which the web manager uses, and rejects messages from modules built after. The generated Python `type_def` is now the text the hash is taken over.
- When a `Client` is created without `definitions` and `PYRTMA_MSGDEF_MODULES` doesn't choose a module, auto-detection raises `MessageDefinitionsLoadError` if more than one compiled definitions module is loaded, naming them; pass `definitions=` to choose. It used to pick one by the order of a set of module names, which could change from run to run. Modules that share one `get_message_definitions`, as after `from defs import *`, count as one. With one definitions module loaded, nothing changes.
- `RTMA_UnifiedLog`, the data logger's command-line interface and `DatasetWriter` create their clients with the core definitions, which are all they use, instead of auto-detecting them.
- `load_message_definitions` loads each file once: loading the same path again returns the same module and classes rather than executing the file again.
- `Client.disconnect()` no longer sleeps for 100 ms. It sends `DISCONNECT`, shuts down its sending side, and waits up to 100 ms for the manager to close its end, which usually takes about a millisecond. A client collected by the garbage collector sends `DISCONNECT` if there is room and closes without waiting.
- A client with a static module ID completes `connect()` only on an ACK addressed to it, or to module 0. A logger is sent copies of other modules' ACKs and used to take the first one. A client asking for a dynamic ID still takes the first ACK, which the manager sends first on a new connection.
- `Client.send_message`, `send_signal` and `forward_message` return `True` when the message was sent and `False` when the socket wasn't writable within the caller's `timeout` and the message was dropped. They used to return `None` and print `x`; the drop is now logged at debug level on the `pyrtma.client` logger. With the default timeout, which blocks, they always return `True` or raise.
- `Client.unsubscribe_from_all()`, and so `reset_subscriptions()`, also forgets paused subscriptions, so a later `resume_all_subscriptions()` doesn't subscribe to them again.
- `Client.pause_subscription([ALL_MESSAGE_TYPES])` records what it paused: `ALL_MESSAGE_TYPES` itself, or every individually subscribed type, all of which the manager drops. `resume_all_subscriptions()` restores them; it used to resume nothing.
- The subscription context managers revert only types still in the state they left them, so changes the body made to those types stand, and restore nothing once the client has disconnected. A `subscription_context()` for `ALL_MESSAGE_TYPES` restores the individual and paused subscriptions it replaced.
- `Client.read_message` discards messages the client isn't subscribed to without decoding them, so a queued message of an unknown type, or one that doesn't match its definition, no longer raises unless the client is subscribed to it.
- The client's socket is non-blocking once connected; waiting is done in `select()`. Code that reads or writes `Client.sock` directly sees a non-blocking socket. A `select()` on it still shows whether a message is waiting, because the client never reads past the message it is receiving.
- A lost connection closes `Client.sock`, as `disconnect()` does, and clears the client's subscriptions; code that calls `select()` on the socket should check `Client.connected` first. A send that fails with any `OSError` raises `ConnectionLost`, not only a `ConnectionError`.
- The client treats a header announcing a negative payload, or one over 1 MiB, the manager's limit, as a lost connection: it raises `ConnectionLost` naming the size and disconnects, since the stream can't be read further.
- `Client.discard_messages()` returns False only if its timeout ended with a complete message still waiting.
- A received message's `recv_time` is when the whole message had arrived, rather than when its header had.
- A `Client` no longer allocates an unused 1 MiB receive buffer.
- `from_random()` fills int64 and uint64 fields across their whole range on every platform; on Linux they previously stayed within 32 bits. Float and double fields now get finite values with random sign and magnitude, rather than values in [0, 1).
- The message manager forwards each message with the sender's `msg_count` unchanged. Recipients previously saw a per-recipient counter in its place. Messages that originate from the manager, such as ACKs, `HELLO`, `GOODBYE` and `FAILED_MESSAGE`, carry a `msg_count` of 0. `Module.msg_count` still counts the messages sent to each module, but is no longer written into headers.
- The message manager drops a client that sends a core message (type below 100) whose `num_data_bytes` doesn't match its core definition, and logs an error naming the type and both sizes. The message isn't processed or forwarded. Previously the manager acted on whatever bytes were in its buffer.
- A message of an unknown core type is no longer forwarded after its sender is dropped.
- When a send to a module fails during a forward, its `GOODBYE` is sent after the forward finishes, so it follows the module's `FAILED_MESSAGE` instead of preceding it.
- The message manager's client connections are non-blocking. It reads whatever has arrived of each client's message into that client's own buffer, and processes the message once it is complete. `MessageManager.read_message` returns `None` until a message is complete.
- The manager sends each message's header and payload in one buffer, built once and shared by all its recipients, so a recipient gets one send instead of two. The bytes are unchanged.
- When a connection takes only part of a message, the manager keeps the rest and sends it as soon as there is room, before anything else. Messages forwarded to that module meanwhile are counted as drops and reported with `FAILED_MESSAGE`, as for a connection with no room at all. A slow consumer is never disconnected for being slow. `Module.send_message` and `Module.send_ack` queue what the connection can't take instead of blocking.
- A client that closes its connection is logged as "Connection closed by the client", or "Connection closed mid-message" with the bytes received, instead of "Wrong number of header bytes". A client dropped for closing or stalling is removed before the warning is logged, so it isn't sent the warning itself.
- `MessageManager.wlist` and `MessageManager.write_timeout` are no longer used. They remain as attributes.
- The message manager sends a `GOODBYE` only for a module that connected, so each `GOODBYE` matches an earlier HELLO. A socket that is closed before it connects, or a module refused at connect, gets none.
- A module refused because its static ID is out of range or already in use no longer takes that ID.
- The reply to `INTRODUCE` has a HELLO for each connected module only. It no longer includes the manager's own entry or sockets that haven't connected, which all appeared with ID 0.
- A socket must send `CONNECT` before anything else. The manager drops a socket that sends any other message first, with a warning, and doesn't act on or forward that message.
- A message whose handling drops its sender, such as a refused `CONNECT`, is no longer forwarded. `DISCONNECT` still is.
- A module can no longer take `DYN_MOD_ID_START` (10000), the first dynamic ID, as a static ID. Static IDs are 1 to 9999.
- `MessageManager.send_to_loggers` takes a keyword-only `exclude`, a logger not to send the message to.
- Each `RTMALogger` has its own `logging` logger, named `pyrtma.logger.<n>` from a counter, instead of one named after `hex(id(client))`. Code that looked a client's logger up by that name should use `client.logger.logger`.
- `RTMALogHandler` no longer turns RTMA logging off when a send fails. A record whose send raises a `ClientError`, such as `ConnectionLost`, is dropped, and sending resumes after the client reconnects. Other errors are reported through `Handler.handleError`. `RTMALogger.enable_rtma` changes only when it is set.
- RTMA log messages replace characters that aren't ASCII with `?`, one for one, in the message, name, path and function name. A path that is too long keeps its end, after `...`; a name or function name that is too long is cut. The wire format and field sizes are unchanged.
- The unified console log waits between connection attempts while the message manager can't be reached. The wait starts at 0.5 seconds, doubles after each failure up to 5 seconds, and starts again from 0.5 seconds after each successful connection. It retries after any `ClientError` or `OSError` from connecting or reading, where it used to retry only after `MessageManagerNotFound` and `ConnectionLost`; failed attempts are logged at debug level.
- Importing `pyrtma.web_manager` no longer changes the root logger. It used to remove the root logger's first handler, whichever that was, and add a `RichHandler`. `main()` now does the setup: it replaces every root handler with a `RichHandler`.
- The web manager's `-d/--defs` option is marked required, so leaving it out gives a usage error with exit status 2 instead of a `TypeError`. Running it with no arguments still prints the help.
- The web manager loads its definitions file once. It no longer also imports the file by its module name or adds its folder to `sys.path`.
- `DatasetWriter` schedules writes and subdivisions with `time.monotonic()` instead of `time.time()`, so a step of the system clock no longer makes them fall due early or late.
- When a `DatasetWriter`'s previous write hasn't finished by the time the next is due, it keeps buffering messages and writes them once the writer is free, logging one warning when it falls behind and one message when it catches up. It used to raise `DatasetWriterError("Unable to write fast enough.")` into the data logger's loop, which stopped the logger. A subdivision that falls due meanwhile waits too, so messages still go to the file they arrived for. There is no limit on what is buffered.
- `DatasetWriter.pause()` and `resume()` return whether they changed anything. `pause()` on a dataset that isn't recording or is already paused, and `resume()` on one that isn't paused, do nothing; `resume "all"` used to reset the elapsed time and subdivide schedule of datasets that weren't paused, and `pause "all"` marked datasets that hadn't started as paused.
- `DatasetWriter.start()` on a dataset that was already started raises `DatasetInProgress` instead of `RuntimeError`.
- `DatasetWriter` creates its files exclusively, so a file that appears after the dataset was added, such as another dataset's with the same path and name, raises `DatasetExistsError` when recording starts or subdivides instead of being overwritten. Text formats are written as UTF-8 rather than in the platform's encoding; their content is ASCII.
- The data logger stops every dataset that would record a message its definitions can't decode, with a stale size or of an unknown type, since that recording would be missing data until the definitions are fixed. Each is reported with `DATA_LOGGER_ERROR` naming the type and the error, then `DATASET_STOPPED`, `DATASET_SAVED` and `DATASET_REMOVED`; its file keeps what was recorded, buffered messages included. Datasets that don't record that type carry on. When no dataset records it, the logger warns once per type and error instead of on every message.
- A request addressed to the data logger is answered to the module that sent it. A broadcast request is still answered with a broadcast, so modules watching the logger keep seeing those replies. `DATASET_STATUS_REQUEST` is still answered to its sender either way, and `DATASET_STARTED`, `DATASET_STOPPED`, `DATASET_SAVED` and `DATA_LOGGER_ERROR` are still broadcast.
- The data logger acts only on requests that are broadcast or addressed to it. The manager sends a logger module copies of messages addressed to other modules, and the data logger used to act on those too.
- `DATASET_START "all"` skips datasets that are recording or have already recorded, with a warning, and reports a dataset that fails to start without stopping the rest.
- A dataset that has recorded is removed once its file is finished, by `DATASET_REMOVE`, by `DATA_LOGGER_RESET` or after it stops, so its `DATASET_SAVED` always comes before its `DATASET_REMOVED`. Its name stays in use until then. A reset also sends `DATASET_STOPPED` for the datasets that were recording.
- When the data logger exits, it waits up to 60 seconds for the datasets' files to be finished, then sends their `DATASET_STOPPED`, `DATASET_SAVED` and `DATASET_REMOVED` before disconnecting, if it still can.
- A dataset whose writer fails is reported with `DATA_LOGGER_ERROR`, `DATASET_STOPPED`, `DATASET_SAVED` for the files finished before the failure, and `DATASET_REMOVED`. It used to get no `DATASET_STOPPED`.
- The data logger sends a `DATASET_SAVED` for every file a dataset saves. One of two files saved in quick succession could be missed before.
- `DATASET_ADD` is checked for capacity, a name in use, and a file another dataset already writes to before the dataset's folder is created. The last is new: two datasets with the same folder, file name and formatter are refused when the second is added.
- `DATA_LOGGER_ERROR` messages from the data logger replace characters that aren't ASCII with `?` and cut text too long for their fields, as `DatasetWriter`'s do.
- `LogReader.load` applies `include` and `exclude` before checking a message against the definitions, so a type the definitions don't have, or have with another size, can be excluded to load the rest of a file.
- `LogReader` logs the messages it skips with `throw=False` as warnings on the `pyrtma.utils.log_reader` logger instead of printing them.
- The QuickLogger formatter keeps a file's message data in memory up to 32 MiB (`QLFormatter.spill_threshold`), then in a file beside the recording named with a `.tmp` suffix (`rec.bin.tmp`, `QLFormatter.spill_suffix`), which is deleted when the file is finished or writing fails. It used to keep all of it in an anonymous file in the system's temporary folder. A spill file left by a crashed logger is replaced by the next recording of the same name.
- The QuickLogger formatter stores data offsets in a 4-byte array instead of a list of Python ints, and writes each batch's headers and data in one call each. For 300,000 small messages, peak memory falls from about 51 MB to under 5 MB; the files are byte for byte the same.
- If the data logger dies while recording, the files it finished are complete, and the file it was writing is lost; it holds message headers but no data, and `LogReader` with `throw=False` reports it as truncated. There is nothing to recover by hand.
- Files are split by size, not time. The `DATASET` struct's `subdivide_interval` field is replaced, in place, by `max_size_mb`: the largest file, in MB of 1,000,000 bytes, from 1 to the new constant `DATASET_MAX_SIZE_MB` (500). Every formatter keeps each file within it and continues in a new file when one is full. The bytes on the wire and every message's size and type hash are unchanged, so clients built before this keep working without rebuilding; their interval arrives as `max_size_mb`, and a value out of range, such as 0, is replaced by 500 with a warning. Rebuilt clients must set `max_size_mb`; code that sets `subdivide_interval` no longer compiles. Regenerate definitions with `build_all_msg_defs.sh` or `.bat`.
- `Dataset(..., max_size_mb=...)` and `DatasetWriter(..., max_size_mb=...)`, keyword-only, default 500, set a dataset's size limit and raise `ValueError` and `DatasetError` respectively when it is out of range. Their `subdivide_interval` parameter is deprecated and ignored, with a `DeprecationWarning` when nonzero. `DATA_LOGGER_CONFIG` reports each dataset's `max_size_mb`.
- `DataFormatter.max_bytes` is an ordinary class attribute, a ceiling that the data logger lowers per file to the dataset's `max_size_mb`.
- The data logger CLI asks for `max_size_mb`, from 1 to 500 with 500 as the default, and accepts message types separated by commas as well as spaces.
- Array lengths must be whole numbers of 1 or more, and other lengths raise `RTMASyntaxError` naming the field. `int32[0]`, or a length expression that evaluates to 0, used to give a scalar in Python and an empty array in C, JavaScript and MATLAB, so their layouts disagreed. A fractional length, such as `STR_SIZE / 3`, used to be truncated, and a negative one raised a raw `ValueError`. A whole number written as a float, such as `STR_SIZE / 2`, is still accepted.
- A field's type spec must match as a whole: trailing text, as in `int32[4] junk`, raises an error instead of being ignored.
- A constant expression may use any number of constants; it used to fail with `RecursionError` past 10. Instead, its nesting depth is limited to `MAX_REFERENCE_DEPTH`. An expression that uses its own name raises `CircularRefError`, and one that doesn't evaluate, such as `1 +` or `1 / 0`, raises `ExpressionExpansionError` instead of the raw `SyntaxError` or `ZeroDivisionError`. Constants are still defined before they are used, which rules out circular references between them.
- A chain of aliases is limited to `MAX_REFERENCE_DEPTH`, raising `RecurisionError`; the limit was 10, raising the built-in `RecursionError`. An alias of itself raises `CircularRefError`.
- String constants can only hold printable ASCII, and other text raises `RTMASyntaxError`. Backslashes and double quotes are escaped in every target, so `C:\data\new` and `say "hi"` compile as written; they used to give a newline, or invalid code.
- Module IDs from `DYN_MOD_ID_START` (10000) up raise `RTMASyntaxError`: the client can't connect with them, and those above 32767 didn't fit the header. User module IDs are 10 to 99 and 200 to 9999.
- A host ID above `MAX_HOSTS` (5) compiles with a warning: a client can send from it, but the client and manager don't accept it as a destination.
- An unknown compiler option raises `RTMASyntaxError`; it used to be ignored silently.
- Importing a `.yml` file still warns, but no longer waits for Enter, which hung non-interactive runs and raised `EOFError` without a terminal.
- In generated JavaScript, every `RTMA.aliases` entry is a function that returns a new value, as `RTMA.SDF` and `RTMA.MDF` entries are. A native alias, such as `RTMA.aliases.MODULE_ID`, used to be the value `0`. An alias of a struct is `RTMA.aliases.<name>`; it was written to `RTMA.SDF` before that existed, and failed when the file loaded.
- The compilers write their C, JavaScript, Python and MATLAB files as UTF-8, rather than in the platform's default encoding.
- The `--combined` YAML file no longer has a `compiler_options` section, which the parser rejected when it was read back, and keeps the `_RESERVED_` IDs of every file rather than only the last file's.
- The Python compiler checks Black's result: when Black fails, it warns with Black's message, and the file is left valid but unformatted. The failure used to go unnoticed.
- `type_def` in generated Python holds the definition's text. It used to include the quotes of a `repr()` inside the string, as in `"'EXIT:\n  id: 0\n  fields: null'"`. `core_defs.py` and the test and example definitions are regenerated; nothing else in them changed.
- Importing `pyrtma.compile` no longer installs `rich`'s traceback handler as the process's exception hook; the compiler's command line still does.
- `Client.send_message` and `send_signal` build each header with one `struct` call, `MessageHeader._pack_into`, and the client sets each received header's `recv_time` the same way, instead of setting the fields one by one through their validators. The bytes sent are the same. In a sandbox, the Python work of a send fell from about 3.8 µs to 1.0 µs.
- `Client` checks `host_id` when it is constructed: an `int` from -32768 to 32767, the range the header holds, or it raises `TypeError` or `ValueError`. Before, `send_signal` raised `ValueError` for a host ID outside that range, and `send_message` sent it truncated.
- `send_message` and `send_signal` raise `TypeError` for a destination ID that isn't an `int` before waiting for the socket, rather than while building the header. `send_signal` checks `signal_type` before waiting too, and also inside `disable_message_validation()`, where a type outside 32 bits used to be truncated.
- `send_message`, `send_signal` and `forward_message` send each message's header and payload with one `send()` call, so a message is one TCP segment rather than two, and they no longer call `select()` before every send. They wait in `select()` only when the socket has no room at all, for up to their `timeout` as before, and return `False` if none appears. A message that had to wait gets its `send_time` when sending starts, as before; `forward_message` sends its header as given. The bytes sent are the same.
- The message manager builds its per-message `FORWARD` debug line only when debug logging is on, and routes each message with less work: no generator-based context manager, a tuple snapshot of the subscribers, and no routing at all for a message nobody subscribes to. In a sandbox, its own work to route a 128-byte message to five subscribers fell from about 4.9 µs to 3.1 µs, without the system calls. What it sends is unchanged.
- The message manager sends an ACK to a module that isn't a logger whole or not at all, as it sends every other message. An ACK the module has no room for is dropped, counted in `Module.drops` and reported with `FAILED_MESSAGE`, and the first of a run of dropped ACKs is logged as a warning. ACKs used to be queued without limit, so a module that sent requests and never read made the manager's memory grow, by about 400 bytes per ACK. A logger is waited for, for its own ACKs too; its own ACK used to be queued without waiting.
- The message manager no longer prints `x` to the console for each message it drops for a slow consumer, or for each send that fails. The drop is reported with `FAILED_MESSAGE` and counted in `Module.drops`, and a failed send is logged.
- A client whose connection the message manager finds reset, such as a killed process, is logged as a warning, "Closed its connection without disconnecting", before its `GOODBYE`, as other drops are. It used to be an error, logged after the `GOODBYE`.

### Fixed

- `disable_message_validation()` turns validation back on when its body raises; it used to stay off for that thread from then on.
- Array fields accept a generator: every value is validated and stored. Validators' `validate_many` reads its input once; with a generator it used to fail or check nothing.
- `MessageBase.get_field_raw()` returns the field's raw bytes, and raises `KeyError` for an unknown name; it always raised before.
- `MessageBase.from_dict()` no longer modifies the dictionary it is given, and its `JSONDecodingError` keeps the original exception as its cause.
- `Message.copy()` works and keeps the classes of the header and data; it raised `AttributeError` before.
- A definitions file that fails to import is no longer left half-initialized in `sys.modules`, so loading it again after a fix works. An exception from its `get_message_definitions()` is raised as `MessageDefinitionsLoadError`.
- `Client.connect` raises `MessageManagerNotFound` for every failure to reach the manager, including a host name that can't be resolved, an unreachable host and a timeout, which used to escape as raw `OSError`s. A malformed server name raises `ValueError`. However `connect()` fails, the client is left disconnected with its socket closed; after an `AcknowledgementTimeout` it used to report itself connected.
- `client_context` passes `auto_detect` to the client, and disconnects it when the body raises.
- `Client.send_signal` accepts dynamic module IDs, as `send_message` does; it used to reject any ID above 256. Both accept `dest_host_id=ALL_HOSTS`, and so does the message manager, which used to log an error and drop such a message.
- A `Client` whose constructor raises, for example for an out-of-range module ID, no longer raises `AttributeError` from `__del__` when it is collected.
- The `connect()` docstring no longer says that logger modules are subscribed to all message types automatically; they aren't.
- `Client.subscribe`, `unsubscribe`, `pause_subscription` and `resume_subscription` accept any iterable. A generator used to change nothing, because it was empty after a first pass.
- `Client.subscription_context()` and `paused_subscription_context()` restore subscriptions when the body raises. With some lists they also used to skip types while checking them: a context could unsubscribe a type that was subscribed before it, or subscribe on exit a type that never was.
- `Client.read_message(timeout)` honors its timeout as one deadline for the whole call. Each message the client wasn't subscribed to, such as the ACK the manager sends for every subscription change, used to restart the full timeout, so a steady stream of them could block the read indefinitely.
- `Client.read_message` no longer blocks past its timeout when only part of a message has arrived; a timeout of 0 never waits. The bytes received so far are kept, and a later read completes the message. The web manager's proxy no longer holds up websocket input on a partial message either.
- `Client.discard_messages()` and `Client.reset_subscriptions()` empty the queue of messages that have arrived. They stopped after the first message the client wasn't subscribed to, so after `reset_subscriptions()` everything but one message stayed queued.
- `ConnectionLost` always leaves the client disconnected. A reset connection used to leave `Client.connected` true.
- One client could freeze the whole message manager (C1): a client that stopped partway through a message, such as one paused between sending its header and its payload, left the manager blocked reading from it, and every other client's connect timed out. The manager now serves the other clients meanwhile, and drops the stalled client after the stall timeout.
- A slow consumer whose connection had some room, but not enough for a whole message, could block the manager in a send until the consumer read again.
- `INTRODUCE` no longer fails with "dictionary changed size during iteration" when a send fails partway through the reply, which dropped the requesting module and cut the reply short. The module whose send failed is dropped and the rest of the reply goes out.
- A module refused at connect for using another module's static ID no longer causes a `GOODBYE` with that ID while its owner is still connected.
- A logger module is no longer sent its own ACKs twice. The extra copy could be taken as the reply to its next request, before that request was processed.
- The manager's subscription table no longer grows with every message type it forwards, or keeps types whose last subscriber left.
- A connection that `select()` can't watch no longer stops the manager with `ValueError`.
- The message manager no longer crashes on a header with a negative `num_data_bytes`. It drops that client and logs an error naming the size; the oversized case now logs the size too.
- An unexpected exception while handling one client's message is logged with its traceback and drops that client, instead of stopping the manager. A failure while accepting a connection is logged and the connection discarded.
- The message manager no longer crashes when several subscribers or logger modules fail at once, as when a rig is power-cycled. Each is removed once, with one `GOODBYE`, and any `OSError` on a send drops the module, not only `ConnectionError`. Removing a module that was already removed does nothing.
- Subscribers that aren't the destination of a directed message are no longer counted as drops, and no longer cause `FAILED_MESSAGE`, when they aren't writable.
- `FAILED_MESSAGE` reports the original message's `msg_count`, rather than the count of whichever module happened to be sent it before the failure.
- The message manager's `sockets` list no longer grows with every connection; a module's socket leaves it when the module is removed.
- Log lines no longer print several times. A new client could inherit the logger of a client that had been garbage collected, with its handlers, so each line printed once per client ever created at that address; after 200 clients, one logger had 400 handlers.
- Logging text that isn't ASCII, such as "kΩ" or "µV", or from a path longer than 511 characters, no longer switches RTMA logging off for the rest of the process.
- `RichLogFormatter` formats a copy of the record. It used to escape `record.msg` in place, so handlers after the console handler, such as the file handler, logged backslash-escaped brackets. It also escapes markup in the message's arguments, and accepts a message that isn't a string.
- Setting `RTMALogger.enable_console` back to `True` after setting it to `False` adds the console handler again; it used to stay off.
- The unified console log connects again; `connect()` was still passed the removed `allow_multiple` argument and raised `TypeError`. It no longer spins a CPU core and floods its log while the manager is absent, and its `--log-level` option works on Python 3.10, where `logging.getLevelNamesMapping()` doesn't exist.
- The unified console log's remote logger shares the module's own client instead of a throwaway `Client()`, which was garbage collected at once.
- The web manager's handler no longer waits for a further message when the proxy reads one it isn't subscribed to, such as a copy still in flight after the web client unsubscribed. Websocket input was not read while it waited.
- A `CONNECT_V2` from a module that has already connected, such as one that follows its `CONNECT`, updates the module's name and process ID, and the manager announces them with a `HELLO`. It used to be ignored, so a client that sent `CONNECT` first kept no name. No second ACK is sent, because a client that sends both waits for one. A different module ID or logger status in it is logged as a warning and ignored. A `CONNECT` from a connected module is still ignored.
- The web manager connects web clients again (C4). Both `CONNECT` and `CONNECT_V2` from a web client raised `TypeError` or `AttributeError`, because they still passed the removed `daemon_status` and `allow_multiple` arguments, and the handler's thread died. A `CONNECT_V2`'s name becomes the proxy's module name. The proxy still always takes a dynamic module ID; a request for a static one is now logged as a warning. A `CONNECT_V2` after the web client has connected updates the name without a second ACK, and a `CONNECT` after it is ignored, as the message manager does.
- A `DatasetWriter` whose write thread fails for any reason, such as a full disk or a subdivision file that already exists, stops recording, records the error for the data logger to report, and closes its file. An `OSError` used to escape the thread unreported, and any failure left the dataset dead but still recording, which made the data logger exit. Files finished before the failure are kept and reported as saved; the failed file isn't finalized, and the messages not yet written are lost, as the error says.
- `DatasetWriter.start()` creates the file before starting its write thread, so a file that can't be created or started leaves no thread running. It raises `DatasetError` naming the cause and removes a file it created.
- A save path that can't be created for any reason raises `DatasetError`; only a missing parent or a permission error did before, and other errors escaped raw.
- `DATA_LOGGER_ERROR` messages built by `DatasetWriter` replace characters that aren't ASCII with `?` and cut text too long for their fields, so a localized system message or a long path can always be reported.
- `DataFormatterKeyError` from registering a formatter name twice carries its text as the message rather than as the dataset name.
- The data logger keeps running when a message can't be decoded with its definitions (C5): `InvalidMessageDefinition` from a message of the wrong size ended it. It also keeps running when a dataset's writer fails, when a request fails with an exception other than a `DataLoggerError`, and on a second `DATASET_START "all"`. Each failure is reported with `DATA_LOGGER_ERROR` and affects only its dataset or request.
- Replies to requests addressed to the data logger reach the module that sent them (C6). They used to be addressed to the logger itself, so C, MATLAB and other clients that addressed the logger never got `DATASET_ADDED`, `DATASET_REMOVED`, `DATASET_STATUS` or `DATA_LOGGER_CONFIG`.
- `python -m pyrtma.data_logger` with no message manager running prints one line and exits with status 1, instead of a traceback.
- The QuickLogger formatter can be constructed again. It read a `size` attribute that `BinFileHeader` doesn't have, so adding a `quicklogger` dataset raised `AttributeError`, which stopped the data logger before the fixes above. Its files have the same version 1 layout as before.
- `LogReader.load(..., throw=False)` reads a truncated file, such as one left by a crashed logger, as far as it goes: every message whose header, offset and data are all in the file, with a warning. It used to raise a raw `ValueError`. With `throw=True`, a truncated file raises a `ValueError` saying so.
- `pyrtma.utils.log_reader`, and with it `pyrtma.data_logger`, imports where `tkinter` isn't installed, such as on headless Linux. `tkinter` is imported only when a file dialog is needed, and its absence then raises `RuntimeError`.
- A QuickLogger recording no longer loses its data once it passes 4 GiB (C9). Packing an offset past 4 GiB raised `OverflowError` before the data was copied in, and the header's 32-bit sizes wrapped. Files now stop at `max_bytes`, and a QuickLogger file is never allowed past the 4 GiB its format can describe even if `max_bytes` is raised.
- `build_all_msg_defs.bat` builds the core definitions from `src/pyrtma/core_defs/rtma.defs`, and the examples from `example.defs`, as `build_all_msg_defs.sh` does; it pointed at a `core_defs.yaml` that doesn't exist.
- `Dataset.poll()` and `process_msg()` handle `DATA_LOGGER_ERROR`, returning errors for their dataset and errors with no dataset name, and store `DATA_LOGGER_CONFIG` in the new `datalogger_config` attribute (C7). Both raised `AttributeError` before.
- The data logger CLI's `add` sends with the CLI's own client, so it uses the server given on the command line; it used to create a second client on the default server, which nothing read.
- The data logger CLI asks again for a name or other text that is too long or isn't ASCII, for message types that would record nothing or aren't IDs, and for more than 64 message types, instead of crashing or adding a dataset that records nothing. A command whose dataset name is too long or isn't ASCII is reported, and the CLI carries on. With no manager running, it prints one line and exits with status 1.
- The `msg_header` formatter's CSV rows no longer end with a comma. Each row had one more field than the header row, an empty one, which made `pandas.read_csv` label every column with the next column's values. Scripts that dropped that empty last column need updating.
- `examples/data_log_example.py` stops sending when interrupted with Ctrl-C. With a packet count, its sending thread ignored the stop request and the script waited for every packet to be sent, at least 2 ms each.
- Aliases of structs work in the parser (H11): an alias may name a struct from an imported file, or one later in the same file, and an alias of such an alias works too. A struct alias used to fail with `TypeError` while checking alignment, and one naming a struct in the same file couldn't be resolved.
- Generated JavaScript constructs messages with alias fields (H10). Every message with one, including the core `CONNECT_V2`, `FAIL_SUBSCRIBE` and `FAILED_MESSAGE`, used to throw "is not a function".
- The elements of struct and message arrays in generated JavaScript are distinct objects (H10). They used to be one shared object, so setting a field of one element set it in all of them.
- Aliases of structs work in every target (H11). C typedefs and MATLAB assignments of an alias follow its struct, and Python aliases follow their class; they used to come before it and fail to compile, run or import.
- A `char` alias array in generated JavaScript is a string, as a `char` array is.
- The padding field the parser adds at the end of a struct records its offset, `Field.offset`, where the last field ends; it was left at -1. Layouts and generated code are unchanged.
- `python -m pyrtma.compile -o <folder>` creates a missing output folder. It used to raise `FileExistsError` saying the output location must be a directory.
- `send_signal` raised `ValueError` once a client had sent 2³¹ messages, about 15 hours at 40,000 a second, because it set its header's `msg_count` with validation on. The count wraps to 32 bits in every header now, as it always did in `send_message`'s.
- `python -m pyrtma.manager -d` allows address reuse: `SO_REUSEADDR` is set before the listening socket is bound. It used to be set afterwards, when it has no effect.
- A `MessageManager` whose listening socket can't be bound, such as when the port is in use, closes the socket before raising `OSError`. It used to be left open.
- A `Client` that never connected closes its socket when it is garbage collected. Every such client, including the one each `DatasetWriter` makes for logging, used to leave its socket open, reported as `ResourceWarning: unclosed <socket...>`.
- The example scripts' definitions, `examples/msg_defs/example_messages.py`, are compiled from `example.defs` as it is now, with the current hashes, by `build_all_msg_defs.sh`, `build_all_msg_defs.bat` and `examples/build_example_defs.bat`, and the README's command makes the same file. The file the scripts imported was stale, with hashes from before the hash change, while the build scripts wrote `examples_messages.py`, which nothing imported and which is removed; `build_example_defs.bat` passed a message file where an index is expected and failed.
- The web manager prints each of its proxies' log records once. A proxy's own console handler printed them, and so did the root logger's, which they propagate to.
